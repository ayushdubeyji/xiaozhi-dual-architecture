Chapter 08 Biomimetic Spatial Audition & Multi-Modal Sensor Fusion

An embodied creature cannot survive in a complex physical environment with vision alone. Optical photons require an unobstructed line-of-sight; they fail around blind corners, disintegrate in zero-lux voids, and offer negligible perceptual warning when a dynamic hazard approaches from behind. In biological phylogenies, audition evolved not as a luxury for symbolic communication, but as an omnidirectional, non-line-of-sight early warning radar operating day and night.

In this chapter, we bridge high-speed silicon state machines with evolutionary biophysics. We detail how the Waveshare RP2040-Zero controller captures microsecond-synchronized acoustic wavefronts across an equilateral 3-microphone planar array using Programmable Input/Output (PIO) hardware, decodes acoustic Direction-of-Arrival (DOA) via GCC-PHAT and SRP-PHAT phase-whitening cross-correlation, rejects ultrasonic multipath artifacts, multiplexes dual time-of-flight laser rangers with sub-millimeter precision, and gates odometric dead-reckoning through high-frequency inertial jerk filtering.

8.1 RP2040 PIO State-Machine I2S Capture for the 3-Mic Equilateral Array

Traditional microcontrollers attempt to interface digital I2S MEMS microphones through fixed hardware peripherals or CPU-intensive interrupt-driven bit-banging. The former approach restricts the engineer to fixed pinouts and limits multichannel scalability (often supporting only 2 channels per hardware I2S peripheral), while the latter introduces non-deterministic interrupt latency and jitter that fatally corrupts sub-microsecond acoustic phase alignment.

The Raspberry Pi RP2040 overcomes this bottleneck through its dual Programmable I/O (PIO) blocks. Each PIO block features four independent, deterministic state machines executing assembly instructions at the system clock speed ($133\text{ MHz}$). To sample three omnidirectional INMP441 MEMS microphones synchronously with zero inter-channel clock skew, we implemented a custom PIO program operating two continuous input pins in parallel with cycle-accurate bit-clock and word-select generation.

Hardware Pin Routing (Option B Direct RP2040 Architecture):
  • GP4: I2S Bit Clock (SCK) — Continuous $1.024\text{ MHz}$ clock shared across all 3 INMP441 microphones (PIO side-set base pin 0).
  • GP5: I2S Word Select (WS / LRCLK) — $16\text{ kHz}$ frame strobe shared across all 3 INMP441 microphones (PIO set base pin 0).
  • GP28: Serial Data Line 0 (SD0) — Multiplexes Mic 1 (Front, $0^\circ$, L/R=GND) on Left Channel and Mic 2 (Rear-Right, $-120^\circ$, L/R=3V3) on Right Channel.
  • GP29: Serial Data Line 1 (SD1) — Samples Mic 3 (Rear-Left, $+120^\circ$, L/R=GND) on Left Channel.

The PIO program executes an 8-instruction cycle that asserts the bit clock via side-set while clocking 32 bits per channel. Below is the production PIO assembly program and C initialization helper from ros2/firmware/pico_3mic_i2s_capture.pio.h: 

// ---------------------------------------------------------------- //
// Pico 3-Microphone Synchronous I2S Capture PIO Program
// Target: Waveshare RP2040-Zero (Rover Main Controller)
// Microphones: 3x INMP441 MEMS I2S (Equilateral Baseline d = 5.5 cm)
// ---------------------------------------------------------------- //

// Raw PIO instructions for dual-data line 3-mic I2S sampling
// Uses sideset on SCK (1 bit) and sets WS
static const uint16_t pico_3mic_i2s_program_instructions[] = {
    // 0: set x, 30        side 0b0    ; 31 data bits loop counter
    0xe03e,
    // 1: set pins, 0      side 0b0    ; Assert Left Channel (WS = 0)
    0xe000,
    // 2: in pins, 2       side 0b1    ; Sample SD0 & SD1 on SCK rising edge
    0x4802,
    // 3: jmp x--, 2       side 0b0    ; Loop through Left Channel 31 bits
    0x0042,
    // 4: set x, 30        side 0b0    ; Reset counter for Right Channel
    0xe03e,
    // 5: set pins, 1      side 0b0    ; Assert Right Channel (WS = 1)
    0xe001,
    // 6: in pins, 2       side 0b1    ; Sample SD0 & SD1 on SCK rising edge
    0x4802,
    // 7: jmp x--, 6       side 0b0    ; Loop through Right Channel 31 bits
    0x0046,
};

static inline void pico_3mic_i2s_program_init(
    PIO pio, uint sm, uint offset,
    uint sck_pin, uint ws_pin, uint sd_base_pin,
    uint32_t sample_rate
) {
    pio_sm_config c = pio_get_default_sm_config();
    sm_config_set_wrap(&c, offset + 0, offset + 7);
    sm_config_set_sideset(&c, 1, false, false);

    // Setup Side-set on SCK (GP4)
    sm_config_set_sideset_pins(&c, sck_pin);
    pio_gpio_init(pio, sck_pin);
    pio_sm_set_consecutive_pindirs(pio, sm, sck_pin, 1, true);

    // Setup SET pin on WS (GP5)
    sm_config_set_set_pins(&c, ws_pin, 1);
    pio_gpio_init(pio, ws_pin);
    pio_sm_set_consecutive_pindirs(pio, sm, ws_pin, 1, true);

    // Setup IN pins on SD0 and SD1 (GP28 and GP29)
    sm_config_set_in_pins(&c, sd_base_pin);
    pio_gpio_init(pio, sd_base_pin);
    pio_gpio_init(pio, sd_base_pin + 1);
    pio_sm_set_consecutive_pindirs(pio, sm, sd_base_pin, 2, false);

    // Clock divider: 16 kHz sample rate * 64 clock cycles per stereo word = 1.024 MHz BCLK
    // SysClock (133 MHz) / (1.024 MHz * 2 PIO cycles/bit) = 64.941
    float div = (float)clock_get_hz(clk_sys) / (sample_rate * 64.0f * 2.0f);
    sm_config_set_clkdiv(&c, div);

    // Autopush 32 bits into RX FIFO
    sm_config_set_in_shift(&c, false, true, 32);
    pio_sm_init(pio, sm, offset, &c);
    pio_sm_set_enabled(pio, sm, true);
}

The state machine outputs a constant $1.024\text{ MHz}$ bit clock and reads GP28 and GP29 simultaneously into the Input Shift Register (ISR). Direct Memory Access (DMA) channel 0 transfers these 32-bit packed audio words into a double-buffered circular memory pool without triggering a single CPU interrupt during the sample window. The RP2040 presents these 3 synchronized channels as a USB Audio Class 2.0 (UAC2) sound card to the Raspberry Pi 3B+ over native USB-C.

8.2 GCC-PHAT & TDOA Acoustic Localization vs Ormia ochracea Tympanal Coupling

In nature, sound localization is dictated by the physical distance between sensory receptors. In large mammals (such as humans with an interaural distance of $\approx 18\text{ cm}$), the brain computes the Interaural Time Difference (ITD) $\Delta \tau = \frac{d \sin \theta}{c}$ and Interaural Level Difference (ILD). However, when the physical baseline shrinks, $\Delta \tau$ collapses below the temporal resolution of individual neural spikes.

Evolutionary Miracle: The Parasitoid Fly Ormia ochracea

The female tachinid fly Ormia ochracea tracks the mating songs of field crickets (Gryllus rubens) in complete pitch darkness to deposit parasitic larvae. Her intertympanal distance is less than $0.5\text{ mm}$, yielding a theoretical maximum acoustic delay of only $1.5\ \mu\text{s}$—far below the $100\ \mu\text{s}$ response time of insect action potentials.

Ormia overcame this physical limit through a rigid cuticular bridge mechanically linking her left and right tympanic membranes. When an incident sound strikes one ear, the mechanical intertympanal rocker oscillates in a combination of rocking and bending modes, amplifying the acoustic phase lag into an apparent time difference exceeding $50\ \mu\text{s}$ and a $12\text{ dB}$ level disparity. This mechanical analog preprocessing achieves an astounding directional accuracy of $\pm 2^\circ$.

On our autonomous rover, we adopt a biomimetic spatial configuration. We mount three omnidirectional INMP441 microphones in an equilateral triangle with baseline side length $d = 5.5\text{ cm}$ ($0.055\text{ m}$) elevated on a 16 cm vibration-damped mast.

$$R = \frac{d}{\sqrt{3}} \approx 3.175\text{ cm}$$ $$\mathbf{r}_1 = (+R, 0, 0), \quad \mathbf{r}_2 = \left(-\frac{R}{2}, -\frac{\sqrt{3}R}{2}, 0\right), \quad \mathbf{r}_3 = \left(-\frac{R}{2}, +\frac{\sqrt{3}R}{2}, 0\right)$$

To prevent spatial aliasing (where the phase delay between elements exceeds $\pi$ radians, creating false grating lobes), the array baseline must satisfy:

$$d \le \frac{\lambda_{\min}}{2} = \frac{c}{2 f_{\max}} \implies f_{\text{alias}} = \frac{343\text{ m/s}}{2 \times 0.055\text{ m}} \approx 3118\text{ Hz}$$

Human vocal formants (F1 through F3) fall squarely between $300\text{ Hz}$ and $3100\text{ Hz}$. By applying a 4th-order Butterworth bandpass filter spanning $[300\text{ Hz}, 3100\text{ Hz}]$, we eliminate spatial aliasing while retaining $>90\%$ of voice acoustic energy.

To resolve the direction of arrival $\phi \in [0^\circ, 360^\circ)$, we compute the Generalized Cross-Correlation with Phase Transform (GCC-PHAT) between each microphone pair $(i, j)$:

$$R_{ij}^{\text{PHAT}}(\tau) = \mathcal{F}^{-1} \left\{ \frac{X_i(f) X_j^*(f)}{|X_i(f) X_j^*(f)|} \right\}$$

Dividing the cross-spectral density by its absolute magnitude whitens the signal, removing reverberant room echoes and isolating the direct line-of-sight delta pulse. For an equilateral triangle, the three non-parallel baseline pairs yield unique geometric delays:

$$\tau_{12}(\phi) = \frac{d}{c} \cos(\phi - 30^\circ), \quad \tau_{23}(\phi) = \frac{d}{c} \sin(\phi), \quad \tau_{31}(\phi) = \frac{d}{c} \cos(\phi + 150^\circ)$$

Unlike a linear 2-mic array (which suffers from mirror-image front/back ambiguity because $\cos \phi = \cos(-\phi)$), our equilateral 3-mic triangle generates a signed, non-degenerate triplet $(\tau_{12}, \tau_{23}, \tau_{31})$ for every horizontal bearing from $0^\circ$ to $360^\circ$, providing unambiguous full-circle spatial localization.

8.3 Dual VL53L0X Time-of-Flight XSHUT Address Multiplexing & Sensor Geometry

Early rover prototypes utilized ultrasonic transducers (HC-SR04) for collision avoidance. However, in real-world environments, ultrasonic sensing introduces fatal failure modes: a $30^\circ$ acoustic cone reflects specularly off angled walls (causing false infinite distance readings), experiences significant phase crosstalk from room acoustics, and introduces $70\text{ ms}$ round-trip blocking delays. Ultrasonic sensing was permanently decommissioned in favor of 940 nm Time-of-Flight (ToF) VCSEL laser ranging.

The STMicroelectronics VL53L0X measures photon flight time at the speed of light ($c \approx 3 \times 10^8\text{ m/s}$), providing millimeter-accurate distance estimation independent of surface reflectance or ambient lighting. However, all VL53L0X modules power up with the same hardcoded I2C factory address: 0x29.

Active ToF Geometry & Bus Addressing:
  • Front ToF: Located at $0^\circ$, longitudinal offset $+11.0\text{ cm}$ from chassis center. Active I2C address: 0x32. Controlled via XSHUT pin on RP2040 GP6.
  • Rear ToF: Located at $180^\circ$, longitudinal offset $-10.0\text{ cm}$ from chassis center. Active I2C address: 0x33. Controlled via XSHUT pin on RP2040 GP7.

To resolve the I2C address collision without requiring external multiplexer hardware (like the TCA9548A), the RP2040 drives the hardware shutdown (XSHUT) lines sequentially during boot: 

// Dynamic I2C Address Re-assignment via XSHUT Sequencing
void initToFSensors() {
    // 1. Pull both XSHUT lines LOW to place sensors in hardware reset
    pinMode(PIN_XSHUT_FRONT, OUTPUT); // GP6
    pinMode(PIN_XSHUT_REAR,  OUTPUT); // GP7
    digitalWrite(PIN_XSHUT_FRONT, LOW);
    digitalWrite(PIN_XSHUT_REAR,  LOW);
    delay(10);

    // 2. Release Front ToF by driving GP6 HIGH
    digitalWrite(PIN_XSHUT_FRONT, HIGH);
    delay(10);
    frontToF.setAddress(0x32); // Reprogram I2C address from 0x29 -> 0x32
    frontToF.init();
    frontToF.startContinuous(33); // 33ms continuous budget (30 Hz)

    // 3. Release Rear ToF by driving GP7 HIGH
    digitalWrite(PIN_XSHUT_REAR, HIGH);
    delay(10);
    rearToF.setAddress(0x33);  // Reprogram I2C address from 0x29 -> 0x33
    rearToF.init();
    rearToF.startContinuous(33);  // 33ms continuous budget (30 Hz)
}

Raw laser distance readings are subjected to a running 5-sample sliding median filter to reject laser shot noise, dropouts, and multi-path spikes before feeding the collision avoidance and mapping pipelines.

8.4 HLK-LD2402 24GHz mmWave Radar Presence Gating & Range Segmentation

While optical ToF lasers provide precise point distances, they can be blinded by transparent glass partitions, black velour drapery, or direct sunlight saturation. Furthermore, lasers cannot distinguish between an inanimate cardboard box and a breathing human being. To provide absolute obstacle safety and human-following tracking, we integrated an HLK-LD2402 24 GHz Frequency-Modulated Continuous Wave (FMCW) radar into the front bumper ($x = +11\text{ cm}$).

Operating in the K-band ($24.00\text{ GHz} - 24.25\text{ GHz}$ with $250\text{ MHz}$ sweep bandwidth), the sensor transmits continuous linear frequency chirps. Reflected signals are mixed with the local oscillator to produce a beat frequency $f_b = \frac{2 B R}{c T} + 2 f_0 \frac{v}{c}$, separating target distance $R$ and radial Doppler velocity $v$.

8.5 400 kHz I2C1 IMU/Magnetometer Sensor Fusion & Dead Reckoning

Accurate odometry on a holonomic vehicle is notoriously difficult. Unlike differential drive robots where wheels roll without lateral slip, Mecanum rollers operate under continuous friction, vector shear, and micro-slippage. Integrating raw wheel encoder counts causes rapid positional divergence.

To establish a drift-free reference frame, the RP2040 polls an MPU6050 6-DoF IMU and a QMC5883L 3-axis magnetometer over its 400 kHz Fast-Mode I2C1 bus (GP2 SDA, GP3 SCL) at a deterministic $100\text{ Hz}$ update rate. Core 0 executes an optimized 9-DoF Madgwick Attitude Heading Reference System (AHRS) filter, utilizing the RP2040 bootrom hardware accelerated floating-point routines:

$$\mathbf{q}_{t} = \mathbf{q}_{t-1} + \left( \frac{1}{2} \mathbf{q}_{t-1} \otimes \boldsymbol{\omega}_t - \beta \frac{\nabla f}{\|\nabla f\|} \right) \Delta t$$
The Rest-Drift Dilemma & Motion-Gated Dynamic Jerk:

Low-cost MEMS gyroscopes exhibit thermal bias drift ($\approx 0.05^\circ/\text{s}$). If dead-reckoning equations integrate attitude continuously while the rover is physically stationary on a workbench, accumulated angular error will rotate the virtual coordinate frame, causing false translation.

To permanently eradicate rest drift, odometric integration is gated by a dynamic jerk and angular rate threshold:

$$\text{Motion Valid} \iff (\text{dynJerk} > 0.045\text{ g}) \lor (|\omega_z| > 0.06\text{ rad/s})$$

Where $\text{dynJerk} = \|\mathbf{a}_t - \mathbf{a}_{t-1}\|_2$. If the measured vehicle jerk and rotation rate remain beneath these thresholds for $> 60\text{ ms}$, attitude integration is held rigid, freezing dead-reckoning coordinates until real mechanical acceleration occurs.

9.1 ESP-NOW to 921,600-Baud UART0 Bridge with CRC16-CCITT Framing

Traditional mobile robotics architectures route Wi-Fi TCP/IP packets between nodes. However, TCP window management, retransmission timeouts, and Wi-Fi roaming handshakes introduce jitter spikes from $20\text{ ms}$ up to $250\text{ ms}$—unacceptable for high-rate teleoperation or closed-loop stabilization.

Our architecture splits the RF reception from the real-time kinematic control. A dedicated ESP32-C3 Mini coprocessor receives raw 2.4 GHz ESP-NOW action frames from the handheld cyberdeck remote at a rock-solid $50\text{ Hz}$ update rate with round-trip latency strictly under $2.5\text{ ms}$. The C3 bridge unpacks the command and re-transmits it across a dedicated high-speed UART link to the RP2040-Zero controller:

High-Speed Inter-MCU Physical Interconnect:
  • ESP32-C3 GPIO 21 (TX) $\to$ RP2040 GP1 (RX) @ 921,600 Baud (8N1).
  • RP2040 GP0 (TX) $\to$ ESP32-C3 GPIO 20 (RX) @ 921,600 Baud (8N1).
  • Fallback baud rate auto-negotiation: 460,800 baud if line errors exceed threshold.

To guarantee data integrity against motor electromagnetic interference (EMI), every packet is encapsulated within an unambiguous byte-stuffed binary frame with a 16-bit Cyclic Redundancy Check:

Offset Field Type Value / Description
0 SYNC0 uint8_t 0xAA — Frame preamble byte 1
1 SYNC1 uint8_t 0x55 — Frame preamble byte 2
2 MSG_TYPE uint8_t 0x01 (Cmd), 0x02 (Telem), 0x03 (Enc), 0x06 (ACK)
3 LEN uint8_t Payload length $N \le 64$ bytes
4 .. 4+N-1 PAYLOAD uint8_t[N] Packed RoverPkt (12 bytes) or TelemPkt (54 bytes)
4+N CRC16_H uint8_t CRC16-CCITT High Byte (covers TYPE, LEN, and PAYLOAD)
5+N CRC16_L uint8_t CRC16-CCITT Low Byte

The CRC16-CCITT implementation utilizes polynomial $0x1021$ with initialization $0xFFFF$:

$$P(x) = x^{16} + x^{12} + x^5 + 1$$

The state machine parser on both microcontrollers consumes incoming bytes through a strict 7-state deterministic automaton: SEEK_SYNC0 $\to$ SEEK_SYNC1 $\to$ GET_TYPE $\to$ GET_LEN $\to$ GET_PAYLOAD $\to$ GET_CRC_H $\to$ GET_CRC_L. Corrupted packets are rejected instantly with zero buffer reallocation.

9.2 40-LED WS2812 Bioluminescent Telemetry Ring & Autonomy Annunciator

To provide intuitive visual biocommunication, the rover chassis is wrapped in an addressable perimeter ring of 40 WS2812B RGB LEDs. Power Rail Safety & Brightness Budget:

9.3 Bayesian Log-Odds Occupancy Grid Mapping & Ray-Marching Free-Space Clearing

To construct a persistent spatial map of the environment without the multi-gigabyte memory footprint of full 3D point-cloud libraries, our telemetry hub implements an exact Bayesian Log-Odds 2D/3D Occupancy Grid.

Let each grid cell $m_i$ possess a binary occupancy state $m_i \in \{\text{occupied}, \text{free}\}$. The probability of occupancy given a sequence of measurements $z_{1:t}$ is tracked via the log-odds ratio:

$$L(m_i | z_{1:t}) = \ln \left( \frac{p(m_i | z_{1:t})}{1 - p(m_i | z_{1:t})} \right)$$

Applying Bayes' rule with a Markov assumption yields the recursive additive update formula:

$$L(m_i | z_{1:t}) = L(m_i | z_{1:t-1}) + \underbrace{\ln \left( \frac{p(m_i | z_t)}{1 - p(m_i | z_t)} \right)}_{\text{Inverse Sensor Model } l_{\text{sensor}}} - \underbrace{l_0}_{\text{Prior Log-Odds}}$$

For each laser ToF reading $z_t$ at bearing $\theta$, our web telemetry engine marches a ray from the rover's position $(x_r, y_r)$ to the sensed obstacle coordinate $(x_{\text{hit}}, y_{\text{hit}})$ using an integer Bresenham ray-marching algorithm:

  1. Traversed Cells along Ray ($r < z_t - \epsilon$): Free space is cleared by subtracting a log-odds decrement: $L \gets \max(L - l_{\text{free}}, L_{\min})$ where $l_{\text{free}} = 0.4$ and $L_{\min} = -4.0$ ($p \approx 0.018$).
  2. Endpoint Hit Cell ($|r - z_t| \le \epsilon$): Obstacle presence is reinforced by adding an occupancy increment: $L \gets \min(L + l_{\text{occ}}, L_{\max})$ where $l_{\text{occ}} = 0.85$ and $L_{\max} = +5.0$ ($p \approx 0.993$).
  3. Temporal Confirmation: To eliminate transient laser dropouts caused by dust particles, a cell is rendered in the WebGL digital twin only after accumulating $\ge 3$ consecutive confirming hits.

9.4 80ms Low-Latency Snapshot Camera Proxy & WebRTC/HTTP Pipeline

Streaming video over embedded links often introduces significant CPU overhead and memory churn. When browsers ingest continuous Motion-JPEG (MJPEG) streams via native <img src="..."> tags, the browser rendering engine retains uncompressed bitmap surfaces in memory, causing memory bloat, socket starvation, and unrecoverable frame buffering delays.

Our architecture implements an asynchronous 80ms Snapshot Proxy on the host server (web_telemetry_server.py at port 8090). A dedicated background Python task queries the Raspberry Pi 3B+ vision coprocessor (192.168.0.103:8081) over LAN, fetching discrete JPEG frames into memory buffers. The web dashboard polls /api/pi_cam/snapshot at $12.5\text{ FPS}$ ($80\text{ ms}$ interval) using double-buffered Image() objects: 

// Low-Latency Double-Buffered Camera Snapshot Engine
const camImg = document.getElementById('camera-feed');
const offscreenImg = new Image();
let fetching = false;

function pollSnapshot() {
    if (fetching) return;
    fetching = true;
    const startMs = performance.now();
    
    offscreenImg.src = '/api/pi_cam/snapshot?t=' + Date.now();
    offscreenImg.onload = () => {
        camImg.src = offscreenImg.src;
        fetching = false;
        const latency = Math.round(performance.now() - startMs);
        document.getElementById('cam-latency-hud').innerText = latency + ' ms';
        setTimeout(pollSnapshot, Math.max(10, 80 - latency));
    };
    offscreenImg.onerror = () => {
        fetching = false;
        setTimeout(pollSnapshot, 200);
    };
}
pollSnapshot();

This pipeline guarantees zero DOM memory accumulation, bypasses browser socket exhaustion, maintains a strict memory footprint under $35\text{ MB}$ on the Pi 3B+, and provides real-time video feedback with sub-100ms glass-to-glass latency.

9.5 12-State Autonomous Navigation Finite State Machine

The rover’s autonomous brain is implemented as a deterministic 12-State Navigation Finite State Machine (FSM) executing on RP2040 Core 0 at $50\text{ Hz}$. The state machine continuously balances forward goal attraction, laser clearance, and mechanical stall detection:

Autonomic Finite State Machine Transitions:
  • CRUISE_CLEAR (0): Forward translation at nominal speed ($v_x = 65\%$). Active while Front ToF clearance $d_F > 450\text{ mm}$.
  • THINKING_SCAN (1): Halts forward motion when $d_F < 450\text{ mm}$; spins in-place $\pm 30^\circ$ to gather a 12-sector polar histogram of surrounding clearance.
  • PLANNING_PATH (2): Evaluates polar histogram sectors; selects optimal exit vector maximizing obstacle distance.
  • VEER_LEFT (3) / VEER_RIGHT (4): Executes holonomic diagonal strafe avoiding detected lateral obstacle.
  • CAUTIOUS_CREEP (5): Low-speed crawl ($v_x = 25\%$) when navigating narrow corridors ($180\text{ mm} < d_F < 280\text{ mm}$).
  • STUCK_DETECTED (6): Triggered if motor drive effort $> 15\%$ but measured IMU jerk $< 0.03\text{ g}$ for $> 350\text{ ms}$.
  • REVERSE_BACKTRACK (7): Reverses along odometry history trail ($v_x = -45\%$) for $600\text{ ms}$.
  • SCURVE_ESCAPE (8): Executes alternating lateral strafe oscillations to free chassis from physical pinch points.
  • COMPASS_PIVOT (9): High-rate yaw rotation to align chassis with magnetic home heading.
  • WALL_FOLLOW (10): Maintains a constant $200\text{ mm}$ lateral distance to contour walls.
  • IMPACT_REFLEX (11): Immediate emergency braking triggered within $10\text{ ms}$ if dynamic jerk exceeds $1.8\text{ g}$.

To conquer mechanical stiction (the high static friction coefficient of 45-degree rubber Mecanum rollers on smooth flooring), the motor driver applies an automated Stiction Kick Pulse: whenever transitioning from a stationary state to motion, motor PWM is boosted to $+45\%$ above target duty for exactly $220\text{ ms}$ before settling to the profiled cruising velocity.
